# Days 29–32: journal, timeline, insights and private reports

Implemented October 17, 2026. Flask/Jinja and the existing workspace/profile authorization remain the foundation. No commit, push or deployment was performed.

## Day 29 — Advanced observations

**Completed:** The existing `observations` table now supports category, author, observed-at versus recorded/updated-at timestamps, timezone, version, archive status, related guided session and caregiver task. Eight starter categories and bounded custom category text are supported. Tags are comma-separated, normalized lowercase, deduplicated, capped at ten and validated. No duplicate journal system or public uploads were introduced.

Creation retains entered values on validation failure. Dedicated detail/edit pages expose metadata and scoped links. Editing preserves original author/creation and uses required optimistic versions; stale updates receive 409. Archive/restore increments the version and preserves the record. Archived entries are excluded from the normal journal, dashboard, and reporting/analytics; timeline visibility can include them explicitly. The existing global care-profile selector controls journal context, and hidden scope fields detect a changed form context.

**Files:** `olumira/models.py`, `migrations/versions/0014_advanced_observations.py`, `services/journal.py`, `services/observations.py`, `olumira/routes/observations.py`, `templates/observations/{form,editor,detail,nav}.html`, `templates/observations.html`, dashboard service/template, shared styles and workspace profile-return handling.

**Migration:** Additive `0013 → 0014`. Original columns/IDs/values stay unchanged. Legacy author/created/observed timestamps stay NULL instead of being fabricated. The legacy date is retained and displayed with unknown time. Default category is General notes and initial version is 1. New scope/time/category/completion indexes support filtering and aggregation. SQLite/PostgreSQL guards validate session/task scope and preserve observation authorship, creation and scope. No SQLite parent-table rebuild.

**Dependencies:** None for this milestone.

**Verification:** `tests/test_journal.py` covers create/edit/conflict/archive/restore, original provenance, category/tags, DST-invalid timestamps, invalid references, workspace/profile isolation, viewer restrictions and CSRF. `tests/test_journal_migration.py` verifies every original column/value, unknown provenance, FK integrity, repeated upgrade and ORM/schema parity. Final results are in the verification report.

**Accessibility/security:** Native labeled forms, details/summary, error/status messaging, focus styles, escaped content, verified membership/role checks, CSRF and scoped server-side reference validation. A caregiver can edit another caregiver's entry but cannot change its author. Viewers can read only. Old clients that omit an edit version must reload; blind overwrites are rejected.

**Limitations:** Attachments deferred because durable private storage is not configured. Tags/custom categories are bounded text, not a separate category-management product. Timezone defaults to APP_TIMEZONE because workspace/profile models do not currently have their own timezone setting; the entry explicitly records its chosen IANA zone. Ambiguous DST times use the first occurrence, disclosed in the form. Legacy unknown metadata stays unknown.

**Manual check:** Select Fictional Fern → Observations → Add an observation → enter title/category/date/time/description/tags → Save. Open detail, edit, archive, use timeline Archived visibility, then restore. Open the same edit twice and verify the second stale save returns a conflict.

## Day 30 — Searchable observation timeline

**Completed:** Server-rendered timeline over the same records; deterministic observed-time descending order with ID tie-breaker. Unknown-time legacy records use their original date as a labeled fallback; their position relative to precisely timed events is inherently approximate. Search covers title, description, tags and category. Category, exact normalized tag, author, status and inclusive date filters combine. Today/7/30/custom ranges use selected IANA timezone and half-open UTC boundaries; custom ranges are bounded to 366 days. Pagination fetches 20 records, preserving filters.

Details and edits carry only allowlisted bounded return-filter fields. There is no browser-controlled return URL. Search escapes SQL LIKE wildcard characters. IDs and scopes are bound parameters. Invalid ranges produce a readable 422 error and clear-filter recovery. Profile switching returns to the timeline.

**Files:** `services/journal.py`, observation routes, journal list/detail/editor/form templates, `templates/base.html`, workspace selector route and shared CSS. `olumira/privacy_logging.py` strips query values from local Werkzeug request logs; application exception logs continue to omit submitted data.

**Migration/dependencies:** Reuses Day 29 indexes; no additional migration or library.

**Verification:** Journal tests exercise chronological/tied ordering, combined category/tag/search/date filters, literal `%` search, pagination, boundary dates, empty results, profile switching and safe detail-return context. The logging test checks that a fictional private query is omitted from the access-log message. Real-browser demonstration exercises edit/return with filters preserved.

**Accessibility/security:** Semantic article/list structure, labeled GET filters, keyboard-operable links/buttons, visible focus and mobile layouts. Only current authorized profile records are queried. GET search terms necessarily exist in browser history; use trusted devices and configure production proxy/access logs to exclude query strings.

**Limitations:** No full-text search server, infinite scrolling or permanent deletion. Offset pagination is deterministic for unchanged data; concurrent new inserts can shift page boundaries. Large applications may later need cursor pagination/search indexes after measured demand.

**Manual check:** Timeline → category Achievements + tag independent + keyword Morning → Apply. View detail → Edit → Save → Back to timeline; confirm filters persist. Seed more than 20 entries to check Next/Previous. Test inclusive custom dates around daylight-saving changes.

## Day 31 — Caregiver analytics and insights

**Completed:** One reusable analytics service supplies SQL counts, category/status aggregates and daily/weekly trends. Inclusive 7/30/90/custom date ranges are bounded to 366 days. Zero event buckets are explicit. IANA boundaries produce 23-/25-hour DST days correctly on SQLite and PostgreSQL SQL expressions. Chart data is generated from actual records; no third-party analytics or chart service is used.

Metrics:

| Metric | Definition |
| --- | --- |
| Completed guided routines | One currently completed RoutineSession whose completed_at is in the period; archived templates do not erase frozen session history. Legacy checklist ticks are excluded. |
| Known-time observations | Unarchived observation whose observed_at is in the period, optionally filtered by category. |
| Date-only observations | Unarchived entries with no observed_at whose original date is in the inclusive selected date range. Shown separately; excluded from time-based charts. |
| Active routines | Currently unarchived templates/checklist activities in the selected scope, independent of reporting period. |
| Completed caregiver tasks | Tasks currently completed with completed_at in period. Reopened/canceled tasks are excluded. |
| Pending handoffs | Current handoffs with at least one unacknowledged intended recipient, including removed recipients. Independent of reporting period. |
| Care-team contributions | Aggregate observations recorded, runs started, handoffs created and recipient acknowledgments during the period. No caregiver rankings. |
| Scheduled completion rate | **Unavailable.** Occurrence rows are materialized only on launch. The schema has no complete historical inventory of eligible/canceled occurrences; launch count is not a valid denominator. Numerator/denominator/rate remain unavailable rather than fabricated. |

Weekly buckets begin on the selected start date. Category filters affect observations only. Counts describe stored activity, not clinical progress or caregiver quality. Current task statuses and recent activity are explicitly labeled as current/all-dates snapshots.

**Files:** `services/insights.py`, observation insights route, `templates/observations/{insights,metrics,charts,period}.html`, shared CSS/navigation, central `analytics.view` permission. Day 29 migration includes scope/completed_at indexes.

**Dependencies:** None; responsive SVG bars with native titles, accessible names and full native HTML table. The long table opens with View exact trend counts to keep the mobile overview usable.

**Verification:** `tests/test_insights_reports.py` verifies a genuinely finished guided session, exact date boundaries, 23-/25-hour DST days, daily zero gaps, weekly grouping, archived templates/observations, category exclusion, real completed tasks and recipient acknowledgments, idempotent duplicate task completion, current pending counts outside the selected period, empty profiles and role boundaries. The browser demo displays actual seeded routine/observation trends and opens the exact-value table.

**Accessibility/security:** Workspace/profile-scoped SQL aggregation, viewer read access, no cross-family totals. Native form labels, chart titles/focusable bars, headings and exact tabular alternative. Charts have no animation. Screen-reader/assistive-technology certification was not performed.

**Limitations:** Scheduled percentage intentionally unavailable until authoritative occurrence history exists. Snapshot metrics cannot reconstruct historical task state. Missing legacy event times are disclosed; no diagnostic inference is made.

**Manual check:** Insights → custom date range covering a completed guided run and observation → Update. Compare daily and weekly tables. Change category and verify only observation metrics change. Switch to an empty profile and verify zero recorded events, with date-only/unavailable explanations retained.

Suggested commit: `Day 31: Build caregiver analytics and insights`

## Day 32 — Private caregiver reports

**Completed:** Builder accepts title, authorized profile, period, timezone/grouping, optional observation category, selected sections and PDF/CSV format. A real HTML preview precedes download. Download recomputes the same scoped data and compares a content/configuration fingerprint; changed records/options return 409 with an updated preview. New generation timestamps are independent of that digest. No report content/configuration is put in a download URL or persisted in public storage.

Sections: overview, guided completions/trends, observation summary/trends, observation details, completed tasks and handoffs created in period. Handoff recipient totals and acknowledgments are current snapshots. Observation detail includes legacy date-only entries, clearly marked; overview keeps known-time and date-only counts separate. All summaries reuse Day 31 calculations.

CSV is UTF-8 with BOM and a stable long-form schema: `dataset,record_id,field,value`. Each selected dataset is explicit; metadata and metric definitions accompany it. UTC timestamps include offsets; missing times stay blank/unknown. CSV quoting uses the standard writer. Untrusted values that could be spreadsheet formulas, including after leading whitespace/control characters, are prefixed with an apostrophe. This changes their spreadsheet display intentionally.

PDFs use forest/sage hierarchy, bundled licensed Noto Sans regular/bold, wrapping paragraphs, repeated table headers, page numbers, generation date, scope/period and informational-use labeling. Long descriptions split as paragraphs instead of being trapped in oversized table rows. Latin, Greek, Cyrillic and standard CJK samples were verified. CJK uses a standard PDF CJK font; unsupported glyphs are represented by their Unicode code point. Complex-script shaping and tagged PDF/UA output are unavailable; accessible HTML preview and CSV alternatives are provided and disclosed.

**Files:** `services/reports.py`, report route, `templates/observations/reports.html`, shared templates/styles, `assets/fonts/{NotoSans-Regular.ttf,NotoSans-Bold.ttf,OFL.txt}`, requirements, report tests/browser script and extended fictional preview seed. Central `reports.generate` permits owners/caregivers and denies viewers. Related authorization/header changes are in workspace services and app factory.

**Migration:** No additional report tables or report-storage migration; uses schema 0014.

**Dependencies:** Runtime `reportlab==5.0.1` (its Pillow dependency is resolved by pip). Development verification adds `pypdf==6.21.1` and `pymupdf==1.28.2`. Noto fonts are bundled under SIL OFL with the license; rendering needs no runtime network or OS font installation. Rendering follows the official ReportLab font guidance: https://docs.reportlab.com/reportlab/userguide/ch3_fonts/.

**Verification:** Report tests cover actual PDF header/content, multipage long notes, accented/Greek/Cyrillic/CJK text, page footers, CSV formulas, sections, profile isolation, viewer denial, CSRF, invalid configuration, export limits, stale preview conflicts and cache/download headers. PyMuPDF rendered the fictional six-page long-note sample; all six pages were visually inspected and automated text bounds stayed within margins. Real-browser PDF and CSV downloads completed and contained the edited fictional observation.

**Accessibility/security:** Verified fresh role and selected-profile checks, scoped queries and CSRF on preview/download. In-memory bytes, constant safe filenames, private/no-store responses, correct content types, nosniff and no public share links/files. The PDF is not claimed to be PDF/UA, and the feature is not a claim of HIPAA/WCAG/legal compliance.

**Limits:** 366 days and 500 total selected detail records, plus a 100,000-unit detail-text budget (each newline adds 20 units to bound extreme pagination); oversize requests fail clearly without silent truncation. Reports are generated on demand, not saved/scheduled. Files downloaded to a user's device are that user's private responsibility. No public sharing, email delivery or background export jobs were added.

**Manual check:** Reports → select Fictional Fern and Last 30 days → choose sections/PDF → Preview report → Download PDF. Change to CSV → Preview again → Download CSV. Compare metrics with Insights using identical filters. Modify an entry after preview in another tab; download should return a refreshed preview conflict. A viewer should receive 403 on the report route; unrelated profile IDs should receive 404.

## Local use, migrations and Render preparation

Install runtime dependencies, back up the existing database with an unused filename, migrate, then restart the process:

```sh
venv/bin/python -m pip install -r requirements.txt
venv/bin/python -m flask --app app backup-sqlite --source database/olumira.db --backup database/backups/before-journal-upgrade.db
venv/bin/python -m flask --app app db upgrade
venv/bin/python -m flask --app app db current
venv/bin/python -m flask --app app run --port 5000
```

The actual local upgrade used an exclusive private backup and compared all original columns/rows across 32 pre-existing tables. Head is 0014. The backup path and actual verification outcomes are in `day-29-32-verification.md`. Downgrade refuses unreviewed loss of journal metadata; rollback requires a reviewed recovery plan and matching database/code backup, never a reset.

A fresh fictional interactive demo uses a temporary database and separate cookie namespace:

```sh
venv/bin/python scripts/preview_routines.py --port 5056
```

It seeds genuinely completed routine sessions, profile observations with category/tags/links, active routines, tasks and handoffs. It does not fake chart counts. Verified fictional account credentials are written to a private temporary access file reported by the command. These fictional accounts use the real development verification-token service. This does not demonstrate real SMTP inbox delivery. The preview lasts until its process stops and does not modify real application records.

Render remains Flask/Gunicorn + PostgreSQL + Redis + configured HTTPS/SMTP. Include `assets/fonts` in the deploy artifact and install `requirements.txt`. No persistent report files, native PDF executable or production PyMuPDF dependency is required. Run migrations once before restarting web workers. PostgreSQL offline SQL compilation passed; live PostgreSQL and a hosted Render smoke test still require a disposable database/deployment. Check export latency under expected production load before launch.

Configure access logs to omit query strings; for Gunicorn a path-only format is `'%(m)s %(U)s %(s)s %(L)s'`. Apply equivalent redaction at the hosting proxy. Local Werkzeug logs are filtered automatically. Keep application SQL echo disabled. Review existing production secrets, HTTPS, mail worker and backup/restore gates from the earlier runbooks; this phase did not deploy or configure external services.
